# Documentation Style Guide

This guide defines the writing standards used in this documentation portfolio.

## Tone and Voice

- Use clear and simple language
- Avoid unnecessary technical jargon
- Write in a professional and neutral tone

## Structure

Each API endpoint should include:

1. Endpoint name
2. Method and path
3. Description
4. Parameters (if applicable)
5. Example request
6. Example response
7. Error codes

## Formatting

- Use Markdown headings for sections
- Use tables for parameters and errors
- Use code blocks for requests and responses
- Keep spacing consistent between sections

## Clarity

- Keep sentences short and direct
- Explain what the user needs to do
- Avoid ambiguity

## Consistency

- Use the same terms throughout all documents
- Keep formatting consistent across files
